Remove kube-rbac-proxy sidecar and use built-in metrics auth

The controller Deployment used gcr.io/kubebuilder/kube-rbac-proxy:v0.8.0
as a sidecar to protect the /metrics endpoint. Kubebuilder has removed
that image, so the controller pod can no longer start from the published
install.yaml.

Replace the sidecar with controller-runtime's built-in authentication and
authorization filter, so metrics are served over HTTPS by the manager
itself and no external proxy image is needed.

- Upgrade Go 1.17 -> 1.22, controller-runtime v0.11.1 -> v0.18.6,
  k8s.io/* v0.23.4 -> v0.30.14 and cert-manager v1.8.0 -> v1.15.5
- Serve metrics on :8443 with filters.WithAuthenticationAndAuthorization
- Replace --metrics-addr with --metrics-bind-address and --metrics-secure
- Remove manager_auth_proxy_patch.yaml and expose :8443 on the manager
- Move to k8s.io/utils/clock and use WithStatusSubresource in tests
- Bump Dockerfile builder to golang:1.22 and controller-gen to v0.16.5
- Update README: metrics section, upgrade note, Go 1.22 prerequisite
- Bump version to v0.1.0
